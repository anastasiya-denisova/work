#  Автоматизированное тестирование API (DummyJSON)

Нужно написать небольшие API-проверки для публичного API DummyJSON: https://dummyjson.com
Документация: - Auth: https://dummyjson.com/docs/auth - Carts: https://dummyjson.com/docs/carts

##  Используемые инструменты
* **Postman** — проектирование запросов, настройка окружения и написание скриптов автоматизации (валидация Chai.js).
* **Newman** — консольный запуск коллекций (CLI-репортер) и генерация HTML-отчетов.


##  Краткий список реализованных проверок

###  1. Авторизация (`POST /auth/login`)
* **Успешный вход:** Возвращает `200 OK` при валидных данных. 
  * *Особенность токена:* Действует заданное время (30-60 мин). Внутри этого промежутка повторно передавать авторизацию не требуется. При истечении времени жизни токена все защищенные запросы возвращают `401 Unauthorized`.
  * *Особенность параметров:* Параметр `expiresInMins` является необязательным (возвращает `200 OK`).
* **Неуспешный вход:** 
  * Отправка с неверным паролем или без пароля возвращает ошибку `404 Not Found`.
  * Отправка без поля `username` возвращает ошибку `404 Not Found`.

### 👤 2. Получение текущего пользователя (`GET /auth/me`)
* С валидным токеном возвращает статус `200 OK`.
* Без токена (тип *No Auth*) возвращает статус `200 OK` (особенность публичного API DummyJSON).

###  3. Получение корзин пользователя (`GET /carts/user/{userId}`)
* Успешный запрос с авторизацией возвращает `200 OK`.
* Запрос без авторизации (*No Auth*) также возвращает `200 OK` (в рамках действия токена)

###  4. Получение корзины по ID (`GET /carts/{cartId}`)
* Успешный запрос с авторизацией возвращает `200 OK`.
* Запрос без авторизации (*No Auth*) также возвращает `200 OK`(в рамках действия токена)
* Передача **некорректного формата тела (body)** возвращает `400 Bad Request`.
* Передача в body **любого произвольного текста в формате JSON** возвращает `200 OK`.

###  5. Создание корзины (`POST /carts/add`)
* Запросы как с авторизацией, так и без нее (*No Auth*) возвращают статус `201 Created`.
* **Аномалии бизнес-логики (userId):** 
  * Независимо от переданного `userId`, API всегда возвращает фиксированный `id` созданной корзины `209`.
  * При передаче `userId` больше `208` сервер возвращает ошибку `404 Not Found`.
  * При передаче `"userId": null` возвращается ошибка `400 Bad Request` с сообщением `"User id is required"`.

###  6. Обновление корзины (`PUT` / `PATCH` `/carts/{cartId}`)
* **Параметр merge:**
  * Запросы **PUT/PATCH c `"merge": true`** возвращают `200 OK` и корзину, где новые продукты объединяются со старыми.
  * Запросы **PUT/PATCH без `"merge": true`** возвращают `200 OK` и заменяют состав корзины только на продукты из тела запроса.
* **Негативные сценарии и аномалии:**
  * Запрос с **пустым телом (body)** возвращает `200 OK` и полностью обнуляет корзину.
  * Передача **несуществующего ID корзины** возвращает `404 Not Found` с текстом `"Cart with id '999' not found"`.
  * Передача **несуществующего ID продукта** возвращает `200 OK` и отдает корзину со всеми позициями, кроме несуществующего товара.
  * Передача **некорректного количества** товара возвращает ошибку `400 Bad Request`.

###  7. Удаление корзины (`DELETE /carts/{cartId}`)
* Запросы с авторизацией и без нее (*No Auth*) возвращают `200 OK`(в рамках действия токена)
* Передача **некорректного формата тела (body)** возвращает `400 Bad Request`.
* Передача в body **любого произвольного текста в формате JSON** возвращает `200 OK`.
